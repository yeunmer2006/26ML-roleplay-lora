# Poster 中文讲解稿

## 一句话介绍项目

我们使用 **4-bit QLoRA** 微调 Qwen2.5-3B-Instruct，让小型语言模型根据角色卡进行角色扮演对话，并通过单轮与多轮实验判断 LoRA 是否真的比“只给基座模型角色卡”更有效。

## 1. 标题与副标题

**LoRA Fine-Tuning for Role-Play Dialogue Generation**

中文含义是“使用 LoRA 微调实现角色扮演对话生成”。副标题说明我们采用了 4-bit QLoRA，在较低显存占用下微调 Qwen2.5-3B-Instruct。

这部分想表达的核心是：我们没有完整训练一个 30.9 亿参数的模型，而是冻结基座模型，仅训练 369 万个 LoRA 参数，占总参数的 0.1193%，最终 Adapter 只有 14.8 MB。

## 2. Problem & Objective：问题与目标

角色扮演模型不仅要回答问题，还要在对话中保持角色的身份、背景、性格、语言风格和行为方式。普通模型即使收到角色描述，也可能给出通用助手式回答，或者在多轮对话中逐渐脱离角色。

我们的目标是：

1. 使用 PIPPA 角色扮演数据微调 Qwen2.5-3B-Instruct。
2. 判断 LoRA 是否能提高角色一致性和沉浸感。
3. 将 LoRA 的提升与角色卡 Prompt 本身的提升分开比较。
4. 检查单轮效果能否延续到多轮对话。

海报中的四个数字分别表示：基座模型有 3.09B 参数、实际只训练 0.1193% 的参数、Adapter 大小为 14.8 MB、最佳实验在单轮配对比较中的胜率为 55.6%。

## 3. Usage / Inference Workflow：使用与推理流程

用户首先提供一张角色卡，其中包含角色姓名、人设、背景、说话方式和外貌等信息。程序将这些字段组合成 system prompt，再加入用户输入，并使用 Qwen 的 chat template 转换成模型输入。

推理时加载两部分：

- 冻结的 Qwen2.5-3B-Instruct 基座模型。
- 训练得到的 LoRA Adapter。

两者共同生成符合角色设定的回复。

需要注意的是，归档评估程序会传入完整对话历史；当前交互式 `chat()` 实现只发送当前用户输入。因此海报中的多轮实验结果来自评估流程，不能直接等同于当前交互程序的多轮能力。

## 4. Data：数据

我们使用 PIPPA-ShareGPT-formatted 数据集。原始数据约有 1.6 万段角色扮演对话，经过格式检查、质量过滤和去重后，保留 11,515 段。

数据按照 8:1:1 划分：

| 数据集 | 数量 | 用途 |
|---|---:|---|
| 训练集 | 9,211 | 更新 LoRA 参数 |
| 验证集 | 1,152 | 观察训练过程和模型泛化 |
| 测试集 | 1,152 | 最终评估，不参与训练 |

处理时保留 system 中的角色卡，并将对话转换为 system、user、assistant 消息。超过上下文长度时，以完整消息为边界删除较早对话，避免从一句话中间截断。

训练损失只计算 assistant 回复部分。system、user 和 padding token 的标签设为 `-100`，使模型学习“如何以角色身份回答”，而不是学习复述角色卡或用户问题。

## 5. Training Method：训练方法

我们采用 QLoRA：

1. 将 Qwen2.5-3B-Instruct 以 4-bit NF4 方式加载，降低显存占用。
2. 冻结基座模型参数。
3. 在注意力层的 `q_proj`、`k_proj`、`v_proj` 和 `o_proj` 上加入 LoRA。
4. 只训练低秩矩阵，保存轻量 Adapter。

主要配置包括：

- LoRA rank `r=8`，`alpha=16`，dropout 为 0.05。
- 单卡 batch size 为 1，梯度累积 8 次。
- 上下文长度分别测试 512 和 1024 token。
- 训练 1 至 2 个 epoch。
- 学习率测试 `2e-4` 和 `1e-4`。

训练在多种 NVIDIA GPU 上完成，因此不同实验的训练时间不能直接作为严格的硬件性能对比。

## 6. Evaluation Protocol：评估方案

每次实验都比较三个系统：

| 系统 | 作用 |
|---|---|
| Base, no card | 基座模型，不给角色卡 |
| Base + card | 基座模型，给角色卡 |
| LoRA + card | LoRA 模型，给相同角色卡 |

这个三路设计能够回答两个不同问题：

- `Base + card` 对比 `Base, no card`：角色卡 Prompt 本身有多大作用？
- `LoRA + card` 对比 `Base + card`：在相同角色卡基础上，LoRA 是否提供额外提升？

所有系统使用相同测试样本和生成参数。我们计算 PPL、多样性、重复率、拒答率和生成性能等自动指标，并使用 MiniMax-M3 对匿名化回答进行评分。配对差异通过 bootstrap 计算 95% 置信区间。

## 7. Judge Dimensions：评分维度

单轮回答从五个维度评分，每项为 1 至 5 分：

| 维度 | 权重 | 含义 |
|---|---:|---|
| Identity | 35% | 是否保持角色身份和设定 |
| Style | 20% | 语言风格是否符合角色 |
| Relevance | 20% | 是否正确回应当前输入 |
| Naturalness | 15% | 表达是否自然、连贯 |
| Immersion | 10% | 是否让对话保持沉浸感 |

多轮评估更关注持续对话能力，其中 Identity 为 25%、Memory 为 25%、Coherence 为 20%，另外还评价 Style 和 Immersion。

## 8. Four LoRA Experiments：四组 LoRA 实验

前四组实验主要调整上下文长度、角色卡保留方式、学习率和训练轮数。

- `train_1` 是初始基线实验。
- `train_2` 尝试更完整地保留角色卡，但重复率升至 40.2%。
- `train_3` 将上下文长度提高到 1024，单轮胜率达到 55.6%。
- `train_4` 使用较低学习率，在保持 55.6% 胜率的同时，将重复率从 23.9% 降到 18.1%。

PPL 越低表示模型越能预测目标数据，但 PPL 低不等于角色扮演质量一定更好。`train_2` 的 PPL 最低，却具有最高重复率，说明只看训练损失或 PPL 会得到片面的结论。

## 9. Single-Turn Quality：单轮质量

在 `train_4` 中，LoRA + card 在身份、风格、相关性、自然度和沉浸感五项平均分上都高于 Base + card。加权分数从 2.703 提高到 2.938。

但是，配对加权差异为 `+0.235`，95% 置信区间是 `[-0.060, 0.558]`。区间包含 0，因此我们只能说观察到了单轮改善趋势，不能声称已经证明 LoRA 有稳定且显著的优势。

## 10. Paired Evidence：配对统计证据

这张图展示每个实验中 `LoRA + card - Base + card` 的配对差异。

- 点在 0 的右边，表示 LoRA 平均更好。
- 点在 0 的左边，表示 Base + card 平均更好。
- 横线是 bootstrap 95% 置信区间。

`train_3` 和 `train_4` 的单轮平均差异为正，但四组实验的单轮置信区间都跨过 0。四轮对话的平均差异全部为负，说明现有 LoRA 模型在多轮质量上持续弱于 Prompt 基线。

## 11. Prompting Is a Strong Baseline：角色卡 Prompt 是强基线

在 `train_4` 中：

- 给基座模型加入角色卡后，单轮加权分数提高 0.765。
- 给基座模型加入角色卡后，四轮加权分数提高 1.270。
- 在此基础上加入 LoRA，单轮再提高 0.235，但四轮降低 0.485。

这说明角色卡本身贡献了大部分提升。评估 LoRA 时不能只与“不带角色卡的基座模型”比较，否则会把 Prompt 的作用错误地算成 LoRA 的作用。

单轮配对胜率也支持这一点：LoRA + card 对 Base, no card 的胜率是 69.7%，但对更严格的 Base + card 基线只有 55.6%。

## 12. Four-Turn Challenge：四轮对话挑战

我们选取 20 个角色，每个角色进行四轮连续对话，检查身份、记忆、连贯性、风格和沉浸感。

`train_4` 中，LoRA + card 的记忆分数为 2.95，与 Base + card 的 2.90 接近；但身份分数从 3.40 降到 2.85，连贯性从 3.35 降到 2.60，最终加权分数从 3.153 降到 2.668。

因此，单轮角色表现有所改善，并不代表模型在多轮对话中也能稳定保持角色。当前 LoRA 更像是学到了角色扮演回复的表面分布，但还没有可靠地学会长期一致性。

## 13. Discussion：结果讨论

第一，LoRA 确实改变了模型的输出分布。LoRA 的 PPL 约为 9.4 至 10.4，明显低于两个基线，说明训练是有效的，而不是 Adapter 没有学到内容。

第二，角色卡 Prompt 已经是一个很强的方案。LoRA 的额外单轮收益较小，而且统计证据还不足。

第三，重复是最明显的问题。`train_4` 将重复率降至 18.1%，但仍约为 Base + card 的 6.3 倍。

第四，多轮表现仍然不足。四个 LoRA 实验的四轮加权分数都低于 Base + card。可能原因包括训练数据中的重复模式、数据质量不足，以及高质量多轮监督不足，但当前实验不能证明只有某一个单独原因。

## 14. Conclusion：结论

我们的结论不是“LoRA 全面优于 Prompt”，而是：

1. 4-bit QLoRA 可以用很少的可训练参数完成 3B 模型适配。
2. 最佳实验对 Base + card 的单轮胜率达到 55.6%，显示出改善趋势。
3. 单轮置信区间仍跨过 0，优势还不稳定。
4. 所有 LoRA 版本的四轮质量都低于 Base + card。
5. 降低学习率可以减少重复，但没有解决多轮退化。

因此，低成本角色适配是可行的，但要实现可靠的角色一致性，还需要更高质量的数据和更强的多轮训练监督。

## 15. Next Steps：下一步工作

后续计划包括：

1. 固定同一份数据快照，使不同实验能够严格对照。
2. 清洗高重复样本，同时保持测试集不变。
3. 增加高质量多轮对话数据。
4. 检查角色信息泄漏和错误角色混入。
5. 增加人工盲评或第二个 Judge，并允许平局。
6. 在相同数据上继续测试学习率、LoRA rank 和 FFN 层目标模块。

四个实验的有效单轮 Judge 样本数分别为 100、70、99 和 99；每组多轮实验包含 20 个角色。不同样本数和 Judge 一致性是结果分析中的限制，比较时需要谨慎。

## 我们具体做了什么

本项目不是只调用现成微调接口，而是完成了从数据到评估的完整流程：

1. 下载并清洗 PIPPA-ShareGPT 角色扮演数据，完成去重、过滤和数据集划分。
2. 实现角色卡与多轮消息格式化，并只对 assistant token 计算训练损失。
3. 使用 4-bit QLoRA 微调 Qwen2.5-3B-Instruct，生成轻量 LoRA Adapter。
4. 设计并运行多组配置实验，比较上下文长度、学习率和训练设置。
5. 实现角色卡驱动的推理程序。
6. 建立三路对照评估，分离 Prompt 和 LoRA 各自的贡献。
7. 实现单轮与四轮挑战、自动指标、匿名 Judge、配对比较和 bootstrap 置信区间。
8. 分析重复、角色一致性和多轮退化等失败案例。
9. 保存实验配置、逐样本结果和汇总报告，并制作最终科研海报。

## 答辩时的简短总结

我们使用 4-bit QLoRA，以不到 0.12% 的可训练参数微调 Qwen2.5-3B。实验表明，角色卡 Prompt 本身已经能显著提升角色扮演质量；LoRA 在最佳配置下取得了 55.6% 的单轮胜率，但置信区间仍包含 0，而且四轮表现低于只使用角色卡的基座模型。我们的主要发现是：LoRA 能以很低成本学习角色扮演分布，但当前数据与训练方法还不足以保证稳定的多轮角色一致性。
