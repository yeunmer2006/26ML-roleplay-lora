# 第六次 LoRA 微调结果记录

> 实验：`train_6`  
> 评估目录：`output/evaluations/train_6`  
> 模型目录：`output/experiments/train_6/final_model`

## 1. 实验目标

第六次微调在 `train_5` 的清洗数据基础上改用 `assistant_windows` 采样策略。
原训练流程每条对话主要监督最近后缀中的 assistant 回复，长对话早期和中期回复
容易被截断。`assistant_windows` 会为一条对话最多构造 3 个目标 assistant turn
窗口，只监督窗口末尾的目标回复，目标是让训练任务更接近多轮评估中的“基于历史
继续扮演同一角色”。

本次运行使用 1024 上下文、`lr=1e-4`、1 epoch、`r=8` LoRA，基座模型为
Qwen2.5-3B-Instruct。

## 2. 核心结论

`train_6` 降低了验证损失，并把 LoRA 重复率进一步降到 17.3%，但没有改善核心
角色扮演质量：

- 单轮综合分：`Base + card 2.693 -> LoRA + card 2.921`
- 单轮胜率：LoRA `50.0%`，Base + card `50.0%`
- 多轮综合分：`Base + card 3.320 -> LoRA + card 2.780`
- 多轮胜率：LoRA `20.0%`，Base + card `80.0%`
- 多轮 memory：`Base + card 2.950 -> LoRA + card 3.700`
- 多轮 identity：`Base + card 3.600 -> LoRA + card 2.550`
- 重复率：Base + card `2.9%`，LoRA `17.3%`
- PPL：Base + card `94.725`，LoRA `11.096`

单轮提升的 95% CI 为 `[-0.085, 0.530]`，仍包含 0；多轮差值的 95% CI 为
`[-0.972, -0.095]`，仍低于 0。

## 3. 训练过程

| 项目 | 结果 |
|---|---:|
| GPU | NVIDIA vGPU-32GB |
| 训练/验证窗口 | 5198 / 261 |
| Optimizer steps | 650 |
| Train loss | 2.362 |
| Eval loss | **2.258** |
| 输入 token | 1,953,936 |
| 总耗时 | 5670 秒（约 94.5 分钟） |
| 训练速度 | 0.115 steps/s |

虽然 `train_6` 的 eval loss 低于 `train_5` 的 2.299，但单轮综合、单轮胜率和
多轮胜率均没有提升。这说明当前验证损失仍主要反映参考回复分布拟合，不能直接
代表角色身份保持和沉浸式对话质量。

## 4. 与 `train_5` 对比

| 指标 | `train_5` | `train_6` | 变化 |
|---|---:|---:|---:|
| PPL | 10.760 | 11.096 | +0.336 |
| 单轮 Identity | 2.950 | 2.820 | -0.130 |
| 单轮综合 | 2.989 | 2.921 | -0.068 |
| 胜率 vs Base + card | 55.0% | 50.0% | -5.0 pp |
| Distinct-1 | 0.708 | 0.737 | +0.029 |
| 重复率 | 17.8% | 17.3% | -0.5 pp |
| 多轮 Identity | 2.600 | 2.550 | -0.050 |
| 多轮 Memory | 3.600 | 3.700 | +0.100 |
| 多轮综合 | 2.780 | 2.780 | 0.000 |
| 多轮胜率 vs Base + card | 25.0% | 20.0% | -5.0 pp |

多窗口样本对 memory 有小幅帮助，对生成多样性也略有改善；但 identity、
coherence、style 和总体多轮质量没有改善。论文中应把它写成负面结果，而不是
“多轮窗口训练成功”。

## 5. 代表案例

成功案例中，`train_6` 的 LoRA 对 Shinji Ikari 面对威胁的反应更短、更贴近角色
恐惧状态，而 `Base + card` 转为安全解释，破坏沉浸感。

失败案例中，Valetta 样本出现明显重复：

> I'm sorry... I'm sorry... I'm sorry...

该案例说明即使整体重复率从 `train_5` 的 17.8% 降到 17.3%，循环生成仍然是
最直观的失败模式。

## 6. 论文写法

可以写：

> Assistant-turn window training slightly improves the memory dimension, but
> it does not improve the overall four-turn role-play score.

避免写：

> Multi-turn window training solves long-context role consistency.
