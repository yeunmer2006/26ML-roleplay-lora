# 修改记录

## 基础训练流程

- 为实现小型 LLM 的角色扮演微调，完成 PIPPA-ShareGPT 数据加载、LoRA/QLoRA 训练、角色卡推理和批量推理流程。
- 为适配不同运行环境，补充本地、Colab 和 RTX 4060 配置，并使用 4-bit 量化、梯度累积、梯度检查点和 8-bit 优化器降低显存占用。
- 为减少正式训练失败和时间浪费，增加 10-step 冒烟测试、50-step 耗时预检、断点续训、模型自动查找/下载和统一训练脚本。
- 为保证实验可复现，记录配置、Git 版本、软硬件环境、数据哈希、训练耗时和指标，并统一管理 checkpoint 与最终 LoRA 权重。

## 数据处理

- 为避免同一角色或相似对话同时进入训练集和测试集造成数据泄漏，将随机逐条划分改为按对话组划分，并修正训练集、验证集和测试集比例计算。
- 为让模型只学习角色回复，将标签改为仅监督 `assistant` 内容，屏蔽 system 和 human token 的损失。
- 为解决不同长度对话无法组成 batch 的问题，完善 padding、标签对齐和数据格式兼容逻辑。
- 为提高数据质量，在评估样本中加入安全词、空回复、过短内容等过滤，并使用固定 seed 和稳定哈希保证多次实验选到相同样本。

## 截断规则

- 发现简单左截断会优先删除角色卡和早期对话，使模型只能根据对话尾部猜测角色，容易学到通用、平均化的角色扮演表达。
- 为保留角色设定，改为始终保留完整 system 角色卡，优先删除最旧对话，并保留有效的 assistant 监督标签。
- 为避免无效监督，删除最后一个 assistant 回复之后的无监督尾部消息，并兼容 assistant 开场、连续 assistant 和空 prompt 等情况。
- 为保证训练与评估口径一致，让训练裁剪和 PPL 计算复用同一套截断逻辑；当“角色卡 + 最后回复”超限时允许超过软预算。

## 评估方式

- 发现仅使用困惑度、关键词命中率等自动指标不能准确判断角色扮演质量，因此引入 MiniMax-M3 作为匿名 LLM Judge。
- 为区分角色卡提示和 LoRA 微调各自的作用，设计三路消融：`Base, no card`、`Base + card`、`LoRA + card`。
- 单轮评估按角色身份一致性 35%、语言风格 20%、上下文相关性 20%、自然度 15%、沉浸感及无 AI 元话语 10% 加权评分。
- 为验证多轮角色保持能力，增加四轮挑战，评估身份、记忆、连贯性、风格和沉浸感。
- 同时保留 PPL、Distinct-1/2、重复率、拒答率、生成速度和显存等自动指标，用于分析质量与效率。
- 为应对 API 限流和长时间评估，加入逐样本落盘、断点续跑、失败重试和 Judge 顺序一致性检查。
- 为减少多次实验的重复生成成本，支持严格校验配置和样本后复用两组基座回答，只重新生成并评估新的 LoRA 模型。

## 训练与验证

- `train_1`：使用 512 上下文、旧左截断、学习率 `2e-4` 训练 1 轮，作为初始基线。4000 条训练样本耗时约 21 分钟，训练损失为 2.364。
- `train_1` 评估：LoRA 将 PPL 从 `Base + card` 的 94.725 降至 10.404，单轮角色身份分数由 2.480 提升到 2.770；但对基座加角色卡的胜率仅 44%，且重复率升至 25.6%，说明模型出现明显重复和多轮质量不足。
- `train_2`：保持其余参数不变，只改用保留角色卡的截断方式，用于验证角色卡截断的影响。
- `train_2` 评估：LoRA 的 PPL 降至 9.441，但单轮身份分数为 2.657，对 `Base + card` 的胜率为 48.6%，重复率升至 40.2%，多轮记忆仅为 2.600，说明仅修正截断还不足以解决重复和多轮生成退化。
- `train_3`：在保留角色卡的基础上将上下文从 512 增加到 1024，用于验证更完整的角色设定和历史对话是否有助于角色保持。4000 条样本训练约 51 分钟，训练损失降至 2.350。
- `train_3` 评估：单轮身份分数提升到 2.970、风格提升到 2.778，对 `Base + card` 的胜率提升到 55.6%，多轮记忆达到 3.650；但重复率仍有 23.9%，多轮综合表现仍低于基座加角色卡。
- `train_4`：为进一步缓解过拟合和重复，将学习率降至 `1e-4`、训练增至 2 轮，并按 `eval_loss` 保存最佳模型。训练约 101.6 分钟，训练损失为 2.278；第一轮验证损失 2.359，第二轮略升至 2.362。
- `train_4` 评估：单轮综合分为 2.938，对 `Base + card` 的胜率为 55.6%，与 `train_3` 基本持平；重复率由 23.9% 降至 18.1%，Distinct-1/2 提升到 0.718/0.809，但多轮综合分降至 2.668，说明较低学习率和两轮训练缓解了重复，却没有解决多轮角色保持问题。
- `train_5`：沿用 `train_4` 的 1024 上下文、`lr=1e-4` 和 2 轮训练，运行清单记录清洗数据目录。训练约 91.3 分钟，训练损失为 2.330，最佳验证损失为 2.299。
- `train_5` 评估：单轮综合分达到 2.989，对 `Base + card` 的胜率为 55.0%，重复率降至 17.8%；但多轮综合分仍为 2.780，低于同次 `Base + card` 的 3.523。
- `train_6`：改用 `assistant_windows` 多轮 assistant 目标窗口，1 轮训练产生 5198 个训练窗口。训练约 94.5 分钟，训练损失为 2.362，验证损失为 2.258。
- `train_6` 评估：重复率进一步降至 17.3%，多轮 memory 提高到 3.700；但单轮胜率降至 50.0%，多轮综合仍为 2.780，对 `Base + card` 的多轮胜率仅 20.0%，说明多窗口训练没有解决多轮身份和风格退化。
